WHAT THIS PROJECT IS
-------------------------------------------------------------------------------
A self-optimizing RAG library. It loops: build a RAG pipeline with some
parameters -> answer a fixed benchmark question set -> an LLM "judge" scores the
answers (Ragas) -> an LLM "optimizer" proposes better parameters -> repeat, keep
the best. Four provider ROLES: embedding, generation, optimizer, judge. Each role
can run on a different backend. Shipped split: embedding + generation LOCAL,
optimizer + judge CLOUD (Mistral).

docs/UNDERSTANDING_PHOENIX_RAG.md is the full guide:
  - Concepts / architecture .......... sections 1-8 and 10
  - How to RUN it from scratch ....... section 9 (9.1 prerequisites checklist,
    9.2 install, 9.3 .env key, 9.4 Ollama, 9.5 config, 9.6 run,
    9.7 troubleshooting table, 9.8 all-cloud shortcut)

      uv pip install -e '.[local]' --python .venv/bin/python
  Run tests with:
      .venv/bin/python -m pytest

  It blocked code-executing Bash commands (but NOT read-only Read/Grep). This is
  the direct reason validate_split_run.py never ran. If a command is refused with
  "cannot determine the safety of Bash", it's the outage, not the command.
- Ollama is live locally with qwen2.5:3b-instruct already pulled. torch is
  already installed, which made the [local] extra cheap to add.
- config/config.yaml is GITIGNORED (it is the live copy the app rewrites). The
  COMMITTABLE example is configs/default.yaml. Edit the right one.
- config/default_config.json contains a real Mistral key but is untracked and
  never committed; the loader drops it on migration. Do not propagate it.
