**Technical Summary: Vector Databases – A Technical Overview**

This document provides a comprehensive technical overview of **vector databases**, specialized systems designed to store, index, and query high-dimensional numerical vectors (embeddings) generated by machine learning models from unstructured data such as text, images, or audio. Unlike traditional relational databases optimized for exact matches, vector databases enable efficient **approximate nearest neighbor (ANN) search**, which is critical for tasks requiring semantic similarity rather than exact equivalence.

The document is structured into nine sections, each addressing a core aspect of vector databases:

1. **Introduction**: Defines vector databases, their purpose, and why they differ from traditional databases. Highlights the need for ANN search due to the inefficiency of brute-force methods for large-scale datasets.
2. **Why Similarity Search Is Different**: Explains the challenges of similarity search in high-dimensional spaces, detailing three common distance/similarity metrics—**cosine similarity**, **Euclidean distance (L2)**, and **dot product**—and the limitations of brute-force search.
3. **Core Architecture**: Describes the four essential components of vector databases: **ingestion pipeline**, **index**, **metadata store**, and **query engine**. Emphasizes the index as the most critical factor influencing performance.
4. **Indexing Algorithms**: Covers three primary indexing methods:
   - **HNSW (Hierarchical Navigable Small World)**: A graph-based method offering high recall (95-99%) with 10-100x speed improvements over brute-force, though memory-intensive.
   - **IVF (Inverted File Index)**: A clustering-based approach that reduces search space by focusing on proximity to centroids, often paired with **product quantization (IVF-PQ)** for memory efficiency.
   - **Flat (Brute-Force) Index**: Guarantees 100% recall but scales poorly, used only for small datasets or benchmarking.
5. **Metadata Filtering**: Discusses strategies for combining similarity search with structured metadata filtering, including **pre-filtering** and **post-filtering**, and their trade-offs in accuracy and performance.
6. **Popular Vector Database Implementations**: Profiles key systems:
   - **Chroma** (embedded, HNSW-based, for prototyping),
   - **FAISS** (optimized library for ANN algorithms, often used as a backend),
   - **Pinecone** (managed cloud service),
   - **Qdrant** (Rust-based, with integrated metadata filtering),
   - **Weaviate** (GraphQL interface with built-in embedding generation).
7. **Evaluating Retrieval Quality**: Introduces **Recall@k** (proportion of true nearest neighbors retrieved) and **latency (QPS)** as primary metrics for assessing performance, noting the inherent trade-off between recall and speed.
8. **Common Pitfalls**: Warns against mismatched distance functions, re-embedding drift (using different models for ingestion and querying), under-provisioned memory for HNSW, and ignoring recall/latency trade-offs.
9. **Summary**: Reinforces the role of vector databases in enabling scalable ANN search, emphasizing the impact of index choice, distance functions, and filtering strategies on system performance.
