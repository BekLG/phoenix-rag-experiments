### **Technical Summary: Vector Databases – A Technical Overview**

This document provides a comprehensive technical overview of **vector databases**, specialized systems designed for indexing and querying high-dimensional numerical vectors (embeddings) generated from unstructured data (text, images, audio) via machine learning models. Unlike traditional relational databases, which excel at exact matches and structured queries, vector databases optimize for **approximate nearest neighbor (ANN) search**, enabling efficient similarity-based retrieval.

#### **Key Sections & Topics**
1. **Introduction** – Defines vector databases, their purpose (handling embeddings), and limitations of traditional databases for similarity search.
2. **Why Similarity Search Is Different** – Explains distance metrics (cosine similarity, Euclidean distance, dot product) and the inefficiency of brute-force search, introducing ANN algorithms as a scalable alternative.
3. **Core Architecture** – Describes the four main components: ingestion pipeline, index, metadata store, and query engine.
4. **Indexing Algorithms** – Details three primary ANN methods:
   - **HNSW (Hierarchical Navigable Small World)**: A graph-based index offering high recall (95-99%) with 10-100x speedup but high memory usage.
   - **IVF (Inverted File Index)**: Clustering-based, memory-efficient but accuracy depends on probing depth; often paired with product quantization (IVF-PQ).
   - **Flat (Brute-Force)**: Exact but slow for large datasets, used for small collections or benchmarks.
5. **Metadata Filtering** – Compares pre-filtering (metadata applied first) and post-filtering (similarity search first) strategies for hybrid queries.
6. **Popular Implementations** – Summarizes key systems:
   - **Chroma** (embedded, HNSW-based)
   - **FAISS** (optimized library for ANN algorithms)
   - **Pinecone** (managed cloud service)
   - **Qdrant** (Rust-based, embedded/server modes)
   - **Weaviate** (GraphQL interface, auto-embedding)
7. **Evaluating Retrieval Quality** – Introduces **Recall@k** (accuracy vs. brute-force) and **latency (QPS)** as key performance metrics, highlighting the recall-latency trade-off.
8. **Common Pitfalls** – Warns against mismatched distance functions, re-embedding drift, HNSW memory constraints, and ignoring recall-latency trade-offs.

#### **Factual Claims & Terminology**
- Vector databases rely on **embeddings** (fixed-length numerical vectors) from models like BERT or CLIP.
- **ANN algorithms** (HNSW, IVF) trade minor accuracy for speed, scaling beyond brute-force limits (~1M vectors).
- **HNSW** is the default in Chroma, Qdrant, and Weaviate due to its balance of speed and recall.
- **FAISS** is a library, not a standalone database, often used as an underlying engine.
- **Recall@10 = 0.95** means 9.5/10 true nearest neighbors are retrieved.
- **Re-embedding drift** occurs when query embeddings use a different model than ingestion, degrading results.
