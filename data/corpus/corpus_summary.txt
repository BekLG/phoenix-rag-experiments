**Technical Summary: Vector Databases – A Technical Overview**

This document provides a comprehensive technical overview of **vector databases**, specialized systems designed for indexing and querying high-dimensional numerical vectors (embeddings) generated by machine learning models from unstructured data (text, images, audio). It contrasts vector databases with traditional relational databases, which are ill-suited for similarity search tasks, and details their architecture, indexing algorithms, implementation trade-offs, and evaluation metrics.

The document is structured into **nine key sections**:
1. **Introduction**: Defines vector databases, their purpose (fast approximate nearest neighbor search), and scope (indexing algorithms, trade-offs).
2. **Why Similarity Search Is Different**: Explains the limitations of relational databases for similarity tasks, introduces distance/similarity functions (cosine similarity, Euclidean distance, dot product), and contrasts brute-force search with approximate nearest neighbor (ANN) algorithms.
3. **Core Architecture**: Describes the four shared components of vector databases: ingestion pipeline, index, metadata store, and query engine.
4. **Indexing Algorithms**: Details three primary ANN algorithms:
   - **HNSW (Hierarchical Navigable Small World)**: A multi-layer graph-based index (default in Chroma, Qdrant, Weaviate) offering high recall (95-99%) with 10-100x speedup over brute-force, but memory-intensive.
   - **IVF (Inverted File Index)**: Cluster-based indexing (often paired with product quantization, IVF-PQ) that trades memory for accuracy, depending on the number of cells probed.
   - **Flat (Brute-Force)**: Exact but slow for large datasets, used for small collections or baselines.
5. **Metadata Filtering**: Discusses pre-filtering vs. post-filtering strategies for combining structured metadata with similarity search.
6. **Popular Implementations**: Compares key systems:
   - **Chroma** (embedded, HNSW-based, for prototyping),
   - **FAISS** (Facebook’s library for optimized indexes),
   - **Pinecone** (managed cloud service),
   - **Qdrant** (Rust-based, embedded/server, HNSW with built-in filtering),
   - **Weaviate** (GraphQL interface, auto-embedding modules).
7. **Evaluating Retrieval Quality**: Introduces **Recall@k** (fraction of true nearest neighbors retrieved) and **latency (QPS)** as key metrics, highlighting the recall-latency trade-off.
8. **Common Pitfalls**: Warns against mismatched distance functions, re-embedding drift (model version skew), HNSW memory constraints, and ignoring recall-latency trade-offs.
9. **Summary**: Reinforces the role of vector databases in enabling scalable ANN search, emphasizing the impact of index choice, distance functions, and filtering strategies on performance.

The document makes **factual claims** about performance metrics (e.g., HNSW recall/latency), architectural requirements (e.g., HNSW’s RAM dependency), and practical trade-offs (e.g., IVF’s dependence on cell probing). It assumes familiarity with terms like *embeddings*, *ANN*, *k-means*, and *product quantization*, and names specific systems (FAISS, Pinecone) and algorithms (HNSW, IVF) as concrete examples. The overall structure is **hierarchical and modular**, progressing from high-level concepts to granular technical details, making it a reference for both conceptual understanding and implementation considerations.
